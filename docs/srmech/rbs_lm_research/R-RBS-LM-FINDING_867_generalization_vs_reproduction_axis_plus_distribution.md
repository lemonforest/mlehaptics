## Item 1 — the generalization⟷reproduction axis (the real finding)
| context key | smoothness `sim(['the','cat'],['the','dog'])` | novel `the bird →` | role |
|---|---|---|---|
| **additive** position-bundle | **0.559** (shares "the@0") | **`sat`** ✓ generalizes | the SMOOTH / generalizing end |
| **octonion coupling-product** (F866) | **0.246** (orthogonal) | `cat` ✗ | the SHARP / reproduction end |

So item 1 is **not** "invent a similarity-preserving octonion key" — the additive Klein-4 bundle **already is** the similarity-preserving (smooth) representation; near/overlapping contexts share additive halves → near keys → it **generalizes** (the novel `the bird` resonates to `sat` via the shared "the@0", because both trained `the <noun>` contexts → `sat`). The octonion coupling-product is the opposite end: orthogonal keys, exact reproduction (F866), zero generalization. **The F865 "crosstalk" was generalization** — conflating similar contexts is the same operation as generalizing over them. This is the memorization↔generalization (bias↔variance) tradeoff, realized as **additive (smooth) ↔ multiplicative (sharp)** context encoding. No single key is "right."

## Item 2 — branching → distribution (numpy-free)
A context with several valid continuations should emit a distribution, not argmax. `['<s>','the']` → `cat` (s1) or `dog` (s2): softmax over the resonance scores (`rational.exp(sim/T)`, T=0.15) gives `cat` 0.207, `dog` 0.181 both weighted (the branch), alongside the generalizing key's noise (`the` 0.287, `<e>` 0.172 — leaked via the shared `<s>@0`). The distribution carries the branch; the noise is the additive key's generalization cost.

## Honest scope
- **The additive generalization is noisy** (the distribution leaks `the`/`<e>` via shared fillers). The sharp coupling key has no such noise but no generalization. The real resonator must **compose** the two (sharp match for seen sequences, smooth fallback for novel) + emit distributions where contexts branch — the next build, not a single key.
- Generalization here is **structural/positional** ("the <X> → sat" via shared "the@position"), not semantic (it does not know bird≈cat); semantic generalization needs semantically-similar word vectors (a separate axis — the co-occurrence/relationship structure).
