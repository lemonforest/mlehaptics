## Verdict
**It is a compositional inference path, not statistical** — the seen-rule engine + the attested shelf + the chord (F658) + the asking-state (F661) — so it is small, GPU-free (F628), and cannot hallucinate (a fact is referenced from the attested shelf, never generated, F640/F688). "Inference" here = compose seen rules over attested content, ask at a gap, render. The kernel is proven (F671/F672/F675/F680).

**Layer 0 is the prerequisite** (the big upstream ask): promote the loose research kernel into a first-class `srmech.storyteller` package module (Python-tier, like `srmech.qm`) + its tool_schema registrations, so the Story Builder ops *join* the 256-entry registry and become discoverable. **Layer 1** = `srmech.storyteller.infer(world, prompt)`. **Layer 2** = a `srmech story` CLI that *introspects* tool_schema so the human needs **no memorised commands** (self-describing) and *asks* on ambiguous intent (self-asking, F661) — exactly the user's "won't need to know all the commands." **Layer 3** = one OpenAI-compatible `/v1/chat/completions` endpoint backed by `infer` is the *universal* connector (AG2 + CopilotKit both speak it), alongside the existing `srmech-mcp` + `srmech-agent` — so the API end is mostly an OpenAI-shim over the existing surface, not a new protocol per framework.

**Dependency edges:** Layer 0 gates 1–3; the `epub_book` adapter (F677/UPSTREAM §33) feeds book-worlds to the shelf; the big-wiki Class-L word-association kernel (F681) enriches it. All compositional, GPU-free. Held open (F394).
