## Verdict
**Two tiers, not one learning kernel.** Tier 1 = the foundational bookshelf (fixed, bit-exact, attested, never retrained — F584). Tier 2 = the progressive adaptive kernel = the conversation context, shaping with use, GPU-free (HDC bind = add, no gradient). Tier 2 adapts every turn; Tier 1's digest never changes.

**Always-learning without changing foundational knowledge.** Because the foundation can be *fixed* (bit-exact), the kernel escapes the data-center-LLM retraining agony — no catastrophic forgetting, no gradient passes. User-adaptation is a cheap additive layer on top of the fixed foundation (the "learning without GPU compute" stance, the two-tier RBS-NN F119/F120).

**The history helix IS the two-axis Möbius.** The conversation/adaptation has exactly the 2-axis structure — turn-axis = the look-ahead/behind temporal seam (σ_E, F592), position-axis = the meaning-class (σ_B, F593). So Tier 2 (the shaped context) is the two-axis Möbius riding the fixed foundation: the conversation context and the kernel's chirality structure are the same object.

**So the build order is right:** populate the foundational bookshelf first (fixed, bit-exact), then add the progressive adaptive layer — not a single from-scratch learning kernel. Favored not privileged (F398); held open (F394).
