### The corrected README sentence

`README.md` says:

> Commits whose paths were all absent on this branch were additionally cherry-picked with `-x`, so their files also sit at their original paths with history.

It should read:

> Of the commits whose paths were all absent on this branch, those that add no `import numpy` were additionally cherry-picked with `-x`, so their files also sit at their original paths with history. That is 12 commits: `6bb07db03`, the five rc426 commits, the three Killing–Yano commits, the two PAL commits and the task931 census `51907645e`. Seven all-absent commits were **not** cherry-picked, because their scripts `import numpy`: `research/sm-inverse-decimation-spike` commits 1–5, `research/spike-140-silicon-net-substrate-coupling-bridge` and `research/spike-141-purple-team-falsification-spike-140-stances`. They are in this archive only.

### Cause

The `TIP.txt` files were generated from a classification file whose per-commit `cherry_pick` flag meant "all touched paths absent on this branch". That flag was computed **before** the no-numpy hard rule removed seven commits from the cherry-pick set, and the generator printed `yes` whenever the flag was true.

Measured in that classification file:

- `cherry_pick = True` for `1742bdea2`, `f25908163`, `9eabb62c8`, `7993124a2`, `df7fb90a8`, `f7f3d5e30` and `ee39d6432`;
- `cherry_pick = False` for `256ba6b78`.

The cherry-picking step then applied the exclusion correctly, but nothing regenerated the column. The README sentence was written from the same pre-exclusion rule.

## 3. Archive tags (maintainer ruling, 2026-09-14)

**The ruling.** Branches whose commits are cited by SHA get an archive tag, so that those SHAs stay reachable after the branch is deleted. Commits already credited to the decoy identity stay as they are; nothing is rewritten.

**Trigger check.** Before tagging, every `.github/workflows` file was read at `origin/main`, at `2658bee5b` and at each of the three tagged commits, looking for triggers a tag push could fire:

- `git grep -nE '^\s*(tags|tags-ignore)\s*:'` found only these patterns: `antikythera-spectral-v*`, `chess-spectral-v*`, `ephemerides-spectral-v*`, `siona-v*` and `srmech-v*`. None matches `archive/*`.
- Every other `push:` trigger is `branches: [main]`.
- `git grep` for `create:` / `delete:` / `release:` or an inline `on: push` found nothing (exit 1).
- After the pushes, `gh run list` showed no run created after 19:25Z.

**Ancestor checks.** Each exited 0:

### One thing the tag does not preserve

`CHANGELOG.md` line 3926 on `main` quotes a past measurement: *"`git branch --contains` → only `research/sm-inverse-decimation-spike`"*. That quote stays true as a record of what the command returned. After the branch is deleted, re-running `git branch --contains 256ba6b78` will print nothing.

The SHA remains reachable. Measured now, `git tag --contains 256ba6b782266c307d4cbe7fe4a38b3fc4d0609e` prints `archive/research/sm-inverse-decimation-spike`. The other half of that evidence, `git merge-base --is-ancestor 256ba6b78 <main>` → NOT-ANCESTOR, is unaffected by deletion.

Likewise, `spike_12b…md:270` names the branch `research/killing-yano-literature-review` at `c85259c`. The branch name will stop resolving; `c85259c` resolves through the tag.
