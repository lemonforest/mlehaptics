## The architecture (bubbles, not one unwrapping)
```
one KNOWLEDGE universe M (simplewiki)  ->  N concurrent SIMULATION BUBBLES, each a different time-front
                                            (different start / phase / traversal state over the SAME M)
coupling = NAVIGATION only: bubble_i's traversal informs bubble_j's next move
          (NOT knowledge merge, NOT state link -- each bubble stays a separate valid simulation)
```
This is *not* unwrapping one timeline (F987) nor superposing k cues into one probe (F976, a *merge*). It is **parallel simulations coupled by navigation hints** — the simulator doing what a single-NOW physical substrate cannot: **occupy several time-fronts at once and let them advise each other.**

## Grounded (rc97, clean toy)
```
A -> {B (dead), C (rich chain)}, both A-edges stored x5  ->  local read of A: B,C near-equal = a coin-toss
SINGLE bubble: cannot disambiguate (no downstream view)
BUBBLE-2 forward-coherence (directed, exclude-backtrack):  B-front 0.000 (dead) | C-front 0.647 (rich)
CROSS-BUBBLE informed navigation picks: C   (correct) -- NO knowledge merged, just a nav hint
```
- **The single bubble is genuinely stuck** (B and C equally strong locally — the F945 BRANCH). Local information cannot resolve it.
- **The concurrent bubble resolves it** by having traversed the *downstream* front: it *knows* C leads to a coherent region and B dead-ends, and hands that as a navigation hint. Bubble-1 moves correctly *because another front informed it* — not because the knowledge was merged.
- **The fix = direction (F967).** The forward walk only worked once it *excluded backtracking to the parent* — the same "second shape / forcing" the user identified (F967): a symmetric (undirected) recall collapses to the hub; a *directed* front navigates. So the bubbles need the forcing to be *fronts* at all.

## The reading (why the live universe forbids it, and what does allow it)
- **The live universe forbids it.** A physical substrate resonates *one* NOW (F950); it cannot run a parallel front and consult it — no closed timelike navigation. Recall-as-unwrapping inherits that single-front limit (F987/F988), which is why *stitching across fronts* stalled.
- **The simulator is allowed.** `[[user_stance_ai_is_not_a_substrate]]`: the LLM/simulation is a puppet, but its *licence* is to **simulate whatever it can fathom** — including *concurrent* counterfactual fronts over its knowledge. That licence *is* the multi-front advantage: not a cheat, the one thing a simulator can do a resonator cannot.
- **Natural cascades that do it (handed to the expert, no lineage):** the user asks if nature has cascades that "work like the brain simulator." Candidate framework readings: the brain's **forward/predictive models** (running counterfactual futures to guide the present action — mental simulation / planning); **imagination** (concurrent "what-if" fronts). These are *exactly* the concurrent-bubble navigation move, and they are the accessibility/BCI foundation (a knowledge-simulating prosthetic). Whether physical cascades (beyond brains) do it is the expert's question.

## What this changes about our goals (the pivot)
- **Stop trying to *stitch* the time dimension into one timeline.** F987/F988 showed within-beat reach; cross-front stitching by merge/unwrap is what "the live universe appears to forbid," and our toys stalled on it. **Don't merge — run concurrent fronts and couple for navigation.**
- **The goal becomes multi-front informed navigation, not one-timeline reconstruction.** Each bubble is a cheap separate simulation over the shared knowledge; the win is *cross-front navigation hints* (resolve a BRANCH one front can't). No knowledge duplication/merge cost — just parallel traversal + hint-passing.
- **It reframes BRANCH (F945).** A single bubble at a BRANCH samples (F945); a *concurrent* bubble that has walked the downstream fronts can *tell it which branch is coherent* — turning an ambiguous BRANCH into an informed COHERENT move. That is the concrete Siona use.
