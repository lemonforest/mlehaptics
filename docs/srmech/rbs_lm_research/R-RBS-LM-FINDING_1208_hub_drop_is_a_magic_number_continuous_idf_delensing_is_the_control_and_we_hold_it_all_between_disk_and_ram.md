# F1208 — The hub-drop `H_DROP` is a magic number: continuous IDF de-lensing (the degree) is the real control; the ≤256 bound is a per-TOME eig block, not a global cap — we hold it all between disk and RAM

**User (2026-07-13):** *"let this top-500 or whatever thing you keep wanting be a number that isn't magic; find what controls it from the encoding; we aren't limited by the same as biology, we can find a way to hold it all between disk and ram."* — the `H_DROP` hub-drop in FULLCLUMP (drop the top-N in-degree words before the Fiedler partition) was a magic number (300/500), and it was **amputating content** (star/music/france fell out at H_DROP=500).

## Measured (simplewiki full weighted kernel, 831k vocab)
1. **No structural break at 500.** Degree decays smoothly — rank 10:48638, 100:26442, 300:17349, 500:13749, 1000:8386, 5000:2807 — and the log-log slope steepens *gradually* (−0.30 near rank 100 → −0.54 near 1000 → −1.0 near 10000). There is **no knee at 500** (or 300). "500" is arbitrary.
2. **The top "hubs" are ENCODING ARTIFACTS, not content.** Top-30 by degree: `born, name, websites, american, part, de, group, city, died, time, january…december, list, related, years` — infobox/template scaffolding + month-names + generic connectors. Dropping *top-N by degree* is the wrong instrument: it removes real content (star/music/france) while the actual junk is **upstream markup leakage**.
3. **Dropping nothing is as good — and keeps the content.** FULLCLUMP with `H_DROP=0` + `true_idf` (continuous de-lensing only): within-fraction **63.1% vs 63.5%** with the drop (identical), and the amputated words return coherent: `star→betelgeuse, pictoris, supergiant`; `volcano→eruption, stratovolcano, conical, popocatepetl, lava, pyroclastic`; `guitar→acoustic, harmonica, virginal, stringed`.

## What controls it (from the encoding)
The **degree itself, applied CONTINUOUSLY as IDF** de-lensing: `idf(w) = 1/(1+deg(w))`, so the edge weight `w·idf(a)·idf(b)` suppresses hub edges smoothly (a hub-lens divided by its mass, F782). There is no cut — the control is a continuous function of the degree the encoding already produces. The hard `H_DROP` was a **blunt, magic discretization of what IDF does smoothly**, and (like the top-16 store, F1207) it was a truncation that *lost data*. **Fix: `H_DROP=0` by default** (drop nothing; de-lens continuously). The residual metadata hubs (born/name/websites/months) are the **upstream cleaning** target (markup / sublanguage kernels, #225/#226; tracked in `residual_gaps`), not a degree-cut.

## We are NOT biology-capped — hold it all between disk and RAM
Biology has a hard working-memory ceiling; **we do not.** The only ≤256 bound in the framework is the **native dense-eigendecomposition block** (`MAX_NATIVE_NODES`), and that is handled by the **recursive Fiedler TOME PARTITION** (bisect to ≤MAXTOME leaves) — a *per-tome* eig block, **not** a global vocabulary cap. So nothing about the eig bound requires dropping global vocab. The correct architecture keeps the **full weighted sparse graph out-of-core** — streamed / sorted-sharded / memory-mapped across disk+RAM — and de-lenses continuously; the dense eig only ever touches a ≤256-node tome at a time. **No truncation to fit memory.** This is the same principle as F1207 (sparse-and-complete storage) applied to the *partition* stage, and it is what makes the enwiki weighted encode (5.2B edges, ~100GB) a **disk↔RAM external merge**, not an in-RAM cap.
