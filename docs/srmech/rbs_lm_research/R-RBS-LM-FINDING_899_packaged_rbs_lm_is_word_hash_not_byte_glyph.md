## (2) BUT it is WORD-HASH, not the byte/glyph LM object
`substrate.encode_word_k4(word) = klein4_bind(klein4_random(D, seed=token_seed(word)), sector)`, where `token_seed(word) = int(sha256(WHOLE WORD)[:hex], 16)`. **Each distinct word string hashes to ONE random vector.** It is byte-blind — orthographically/morphologically related words are orthogonal. The byte/glyph core (F865/F612) instead builds a word UP from its bytes: `bundle_odd(klein4_bind(byte_k4(byte), pos_key(i)))` — language-agnostic, sub-word structure preserved.

The packaged encode carries **zero** sub-word structure (every near-word pair sits at chance); the byte/glyph core carries it (related pairs 0.56–0.71) while keeping genuinely-unrelated words at chance. **The byte/glyph LM object lives ONLY in the research probes — it was never graduated into the packaged RBS-LM object.
