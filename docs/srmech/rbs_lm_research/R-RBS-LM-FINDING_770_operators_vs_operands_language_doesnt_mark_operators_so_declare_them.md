# F770 — operators vs operands: function words are the language's OPERATORS; math marks them by form, language doesn't, so they must be DECLARED (rules), while operands are derived by MEANING

**Date:** 2026-06-15 · **srmech:** 0.7.5rc155 · **Composes:** F768 (why the routing stoplist exists — this REFRAMES it: not a "prior standing in for a measurement" but the operator grammar language requires), F766 (meaning-anchored depth = the OPERAND side done by meaning), F752/F753 (the FRAME-vs-TOPIC channel = the contextual role-reader for ambiguous words), the §1 A–N primitive vocabulary (the framework's operators), DUALITY.md (structure/field vs content/excitation) · **User direction (2026-06-15):** "so they are like operators vs operands in the language then? with math it's easy to find operators because they look different, but in language, all things are words and I let us forget this. so then we do need rules defined."

## The insight
Function words vs content words = **operators vs operands**. In **math**, an operator is a *different glyph class* (`+` `×` `∫` ≠ `3` `x`) — the FORM carries the type, so operator-detection is free. In **language**, the operator and operand **wear the same clothes** — "tell", "about", "more" are letters-on-a-line exactly like "tomato". The role is NOT in the form, so it cannot be read off the form: **it must be DECLARED.** This is why "derive function-ness from the meaning of the word" kept failing — operator-ness is a grammatical ROLE, not a semantic property.

The linguistics name is **closed-class vs open-class**: operators (function words) are a CLOSED class — finite, slowly-changing, a few hundred (the/of/how/about/made/more…); operands (content words) are an OPEN class — unbounded, always growing. Closed-class membership genuinely IS a list. The exact engineering analogy: **reserved keywords** in a programming language (`if`, `for`, `return` are formally indistinguishable from `foo`, so the language *declares* them reserved). **The routing stoplist is Siona's reserved-word table for natural language** — not a hack, but the operator grammar.

## The clean division it gives (resolves the session's tension)
> **Meaning derives the OPERANDS. Rules declare the OPERATORS.**

This reconciles two things that looked opposed:
- **F766** (meaning-anchored depth, definitions→anchors) was RIGHT — it reads the *operand/content* by meaning.
- **the stoplist** is ALSO right — operators are *declared*, not measured.
The category error all session was trying to do **operators by meaning**. Operators get rules; operands get meaning.

## Three layers (and how this refines F768)
1. **Declared operators** — the closed-class core (the/of/how/about/made). Rules BY NECESSITY; no meaning-derivation possible or needed. This is the stoplist's core. (F768 called the stoplist "a prior standing in for a measurement" — that was only half-right; the closed-class core is genuinely rules, not a stopgap.)
2. **Contextual-role for the ambiguous** — words that can be EITHER ("the Milky **Way**" = operand; "in a **way**" = operator; "the **answer**" = operand; "**answer** briefly" = operator-ish frame). These get no fixed label — their role comes from the **FRAME-vs-TOPIC channel** (F752), the sentence's structure. This is the genuine residue F768's aboutness-gradient was pointing at.
3. **Meaning for operands** — the open-class content, routed/derived by meaning (gloss, relations, the F766 definition anchors).

## Framework resonance
The **A–N primitives ARE the operator vocabulary** (Class A content-address, I cyclic, L Laplacian, M bind…); the substrate content they act on are the operands. Math made the operator/operand split *visible*; natural language *hid* it (everything is a word); the declared rules put it back. There is a light two-truths resonance (DUALITY.md): operators ≈ the structural/field side (how things relate), operands ≈ the excitation/content side (what is there) — the rules carry the structure, the meaning carries the content.

## Verdict
Function-vs-content is **operator-vs-operand**, and the reason it needs declared rules is that **language — unlike math — does not mark operators by form** (closed-class operators are formally identical to open-class operands; cf. reserved keywords). So the right architecture is a clean division: **declare the operators (the stoplist / the A–N op vocabulary), read the ambiguous by role (frame/topic channel F752), and derive the operands by meaning (F766).** This vindicates the stoplist (it is the language's reserved-word table, not a patch) and refines F768 (the closed-class core is rules by necessity; only the gradient middle is the role/aboutness story). The session-long pull to "derive everything from meaning" was over-applying the operand rule to the operators.
