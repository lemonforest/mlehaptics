## Verdict
**Form layer ready; sub-languages not — and the markup tells us exactly which is which.** The F579 form tiers carry over to full enwiki at high rates. But full wiki embeds sub-languages (natural language 21.7%, phonetic 18.7%, programming ~3%, chemistry/music/hieroglyph) that the form kernel would *strip* — so those parts are not coherent. Each is tagged by an attribute (`lang=`, `{{lang|xx}}`, `<ce>`), and **that attribute is the determinative (F595 σ_B) that routes the span to the right sub-language kernel** — the routing is supplied, not guessed.

**Deliverable:** the `formatting_language_kernel.toml` now carries a sub-language router (6 sub_language kernels + 7 structural tiers + a `[router]` note keyed on the `determinative` field). **<hiero> already routes to the F582 Egyptian kernel — proof the architecture works.** The next build is the per-sub-language kernels (a per-language programming kernel = Class-B+D; embedded-NL router; IPA; music = Class-I; chemistry = Class-J), each a kernel-the-srmech-way (its own TOML, F584 persistence). **The SS-FULLWIKI gate now has a concrete, measured blocker list** — full-wiki encoding stays gated until those sub-language kernels exist (else 1-in-5 articles with {{lang}}/IPA lose coherent content).
