## The observation (1): genome is Python orchestration over C core ops
The blind, un-cancellable 3.4 h run IS this — the partition recursion + bookkeeping live in Python, calling C-native kernels for the heavy math. Consequences: (a) `genome_from_graph` can't run on a **C-only / microcontroller host** yet (breaks the 1:1-parity commitment for the genome layer); (b) there's no natural place for a progress/cancel signal (composes **§101** — a C-native genome path would expose progress at the C level for free); (c) it's slow because the orchestration, not just the math, is interpreted. **A C-native genome path is a real srmech item** (separate from, and larger than, §101).

## The pre-processing (2): the scattered graph-L IS plasmid DNA — a two-stage encode
The insight lands exactly on the attested biology (F1251). Split the pipeline:

| stage | what | biology (F1251) | cost |
|---|---|---|---|
| **1. EXTRACT** — dense → **sectional plasmid graph-L** | each document/batch → a small local co-occurrence subgraph = one **plasmid section**: append-only, mobile, *unorganized relative to the core* | **plasmid / accessory genome** — you accumulate relationships as plasmids as you ingest | cheap, STREAMING, once-per-document |
| **2. ORGANIZE** — sectional plasmids → **organized nuclear genome** | the genome step **integrates** the plasmid sections into the conserved structure; shared content coalesces into the minted nuclear core, the rest stays plasmid | **nuclear-core formation** via `integrate` / HGT (F1244/F1251); the ~16/84 ratio — a minority organizes into the core | the repeatable "genome step" |

So *"the organized part = the genome step"* is exactly right: **stage 1 = plasmid (scattered), stage 2 = nuclear (organized)**.

### Two wins
1. **Encode-once / append (F1247).** Relationships are extracted ONCE into plasmid sections. Add a document → append a plasmid; **never re-run dense→graph-L**. Re-encode = re-*organize*, not re-extract. This also **retires the loose 916 MB `simplewiki_directed_sparse_kernel.json`** — which is genuinely the loose-JSON anti-pattern *at the graph-L layer* ([[feedback_persist_genome_native_not_loose_json]]); it should be plasmid-native sections, not a monolithic dense file.
2. **The organizing becomes INCREMENTAL — this attacks the blind monolithic `recursive_cut`.** If the input is already sectioned into plasmids, the genome step **integrates** plasmids into the nuclear core (per-section, cheap, parallelizable) instead of running one `recursive_cut` on 39M undifferentiated edges from scratch (the 3.4 h blind block). **The sections ARE the pre-clustering** — biology never partitions a monolithic genome; it accretes plasmids and integrates the conserved ones. So stage 1 does the cheap local structuring; stage 2 only has to *merge + promote-to-core*, not *discover all structure at once*.

### Why it's not moot
It changes the genome step's **input contract** from "one dense graph, partition it" to "a bag of plasmids, integrate them" — biology-exact AND asymptotically cheaper (incremental integrate vs from-scratch spectral partition). Even once `genome_from_graph` is fast/C-native, the sectional-plasmid intermediate is the right SHAPE: it makes ingestion append-only, re-encode incremental, and the organizing a merge rather than a global solve. It is the [[feedback_encode_once_render_on_the_fly_epigenetic_reader]] principle one layer up: extract the relationships once (plasmids), organize on demand (nuclear), never re-extract.

## The srmech ask (a pipeline stage + a C-native genome path)
1. **A `plasmid`-native sectional graph-L store** — dense/text → append-only per-section co-occurrence subgraphs, each a Tier-1 stick/plasmid chromosome (genome-native, not loose JSON). Streaming, incremental. This is stage 1.
2. **`genome_from_graph` (or a new `genome_integrate_plasmids`) that consumes the sectional store** and organizes by INTEGRATING sections (merge + promote conserved content to a minted nuclear core) rather than partitioning a monolithic graph from scratch. This is stage 2, and it should be incremental (add a plasmid → re-integrate cheaply).
3. **A C-native genome path** (the observation above) — so the genome layer runs on a C-only host and exposes §101 progress/cancel at the C level.
