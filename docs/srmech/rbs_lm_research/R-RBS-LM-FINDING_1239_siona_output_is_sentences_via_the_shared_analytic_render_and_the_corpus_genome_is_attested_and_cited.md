## 2. "why does genome have a json?" + the ATTESTED genome
The genome is TWO files: `turns.bin` (the 312 MB packed binary body — all chromosomes) and **`manifest.json`** (the sidecar header). The JSON is the genome's self-describing **provenance + integrity header**: the chromosome table (where `graph`/`vocab` live in the binary + per-chromosome `cap_sha256`), `format_version`/`leaf_dim`/`n_turns`/`body_sha256`/regions, and the AMSC **attestation** block. It's JSON (not baked into the binary) so provenance + integrity are inspectable WITHOUT decoding the body — srmech ships a C JSON parser for exactly this (a C-only/MCU host reads it). It is the AMSC-native provenance carrier.

**And that manifest is where the attestation lives — it held only `genome_save`'s DEFAULT placeholder** (`license: CC0`, `source_url: srmech.net/genome/persistence`, epoch `retrieved_at`): it attested the persistence FORMAT, not the CONTENT. `genome_save(strand, path, the_one, labels)` takes NO attestation argument, so it can only write the generic one.
**Fix:** patch the EXISTING manifest's `attestation` in place (no second JSON) + add a `rendering`/cite block, with the real provenance: `source_url: dumps.wikimedia.org/simplewiki`, `license: CC-BY-SA-4.0`, `retrieved_at` = the source kernel's mtime, `response_sha256` = the genome body hash, `collector_descriptor_path/hash` = the build script. `genome_load` is unaffected (chromosome table untouched — verified 831,139 vocab still loads). Made reproducible as **`R-RBS-LM-ATTESTGENOME`** (a committed tool; `genome_save`'s no-attestation-arg limitation is the reason it's a post-save patch — a candidate srmech ergonomics ask). `corpus_store._load_attest` reads it; **`corpus_store.cite()`** returns the `cite_as`; every corpus reply ends with "*(Simple English Wikipedia (directed co-occurrence), CC BY-SA 4.0 — dumps.wikimedia.org/simplewiki)*" — an attested genome, exactly like an attested knowledge kernel (MPM).
