## 1. Is klein4 "already carrier-supported / an output type"? — YES, it is the HV carrier
`klein4_random`/`klein4_bind`/`klein4_bundle`/… all **return `srmech.amsc.hv.HV`** (verified rc241) — srmech's shipped hypervector carrier (the HDC peer of `Mat`/`Vec`). So **klein4 is not a separate type; it is the (F₂)²-sector *mode* of the HV carrier**, expressed through the `klein4_*` op family (25 ops), and its output type is already a first-class carrier. Nothing to add for "klein4 as an output type" — it exists. *(The one open design choice: a **typed `Klein4` view** of HV so operators dispatch by type (`bind(k4,k4)` auto-selecting XOR) instead of by op-name (`klein4_bind`) — a config-driven `[class]` descriptor per `[[feedback_prefer_config_driven_toml_classes]]`. Cleaner ergonomics, bigger change; optional, not required.)*

## 2. "Do we need to make ALL hdc objects klein4 by observing nature and cosmos?" — the substrate IS full-chirality; BSC is its *named* shadow
The framework's own reading (F130/F132): the substrate is **4-way chirality** — γ₅ × iω₇ = the (F₂)² Klein-4 group — and plain 1-bit **BSC (bipolar) hdc is the chirality-COLLAPSED projection**. srmech makes this literal: **`klein4_project_axis(v, axis='gamma5') → bipolar {−1,+1}`** is the *named op* that collapses a full klein4 HV down to a 1-axis BSC shadow. So "observing nature and cosmos" → **the COMPLETE hdc object IS Klein-4; BSC is `project_axis` of it.**
But **not** "force every op to klein4," for two honest reasons:
- **No-privileged-representation** ([[feedback_no_privileged_primitive_classes]]): keep BSC where chirality is irrelevant (presence/magnitude) — it is cheaper (1 bit vs 2) and correct there. The collapse is a real feature of the projected substrate (F552), not an error.
- **Klein-4's own READ is coarse** (F1214/F1215): swapping BSC→klein4 in the *working representation* does not fix ORDER — order lives in the directed Laplacian **STORE** (F1216), itself a full-chirality (signed/magnetic) object.
**So the rule is: use the full-chirality object (klein4 HV for reads, directed/magnetic Laplacian for the store) wherever DIRECTION / CHIRALITY / ORDER is load-bearing; keep BSC where it is not.** "Make it klein4" and "store the directed Laplacian" are the same move — *use the object, not the `project_axis` shadow* — at two layers (F1222's 3D_s-shadow / 7D_g-store split).

## 3. The order operator ALREADY EXISTS → item 5 (`klein4_permute`) WITHDRAWN
The "does weak just mean use an existing op?" gate, applied and **settled YES**: Klein-4 has commutative `bind`/`bundle` (no order), and the generic `hdc.permute` is BSC-byte-only — **but** `klein4_phase_bind(hv, frac)` + `klein4_phase_key(D, frac)` (UPSTREAM §59, F861) bind a **continuous position-phase** into a klein4 HV (the FHRR position trick: element at position p → `phase_bind(v, p/L)`, invertible), and `klein4_compose(parts)` is the scale-invariant **ordered** role-filler compositor (F900/F901), with `klein4_triality_cycle` the order-3 S₃ generator. **So the sequence/order role is already covered — there is no need for a dedicated `klein4_permute`.** Item 5 is withdrawn from #1390; the correct guidance is "encode order via `klein4_phase_bind`/`klein4_compose`." (This is the [[feedback_introspect_srmech_before_python_dispatch]] reflex catching a would-be redundant op *before* filing.)

## 4. `graph_to_kernel` / `kernel_to_graph` (item 2) — PROTOTYPED, 8/8 byte-exact
`R-RBS-LM-GRAPH2KERNEL_…py`: the domain-free codec abstracted from the hand-rolled `_ints_to_syms`/`kernel_to_ints` (NIVDIRECTED/NOWCURVATURE), tested against the **real** directed word kernels (`word_to_kernel`):
- **struct round-trip 8/8** — `(vocab_size, edges, weights, charges, node_ids, extras)` byte-exact through the self-describing format.
- **genome-native persist 8/8** — `graph_to_kernel → genome_save (content-addressed) → genome_load → kernel_unpack → kernel_to_graph` reproduces the graph exactly.
- word-reconstruct 5/8 — the 3 misses (mississippi, reappear, committee) are **NOT** codec failures; they are a pre-existing `word_to_kernel` limitation: it **skips self-loops (`u==v`)**, so double letters (`ss/pp/tt/ee`) are dropped by the *encoder* before serialization. (Breadcrumb: the word encoder is lossy for repeated consecutive glyphs — a separate fix if we want exact double-letter round-trip.)
- Proposed signature (for #1390): `graph_to_kernel(vocab_size, edges, weights, charges=None, *, node_ids=None, extras=(), leaf_dim, label, the_one) -> strand` + `kernel_to_graph(chroms, the_one, n_syms) -> {vocab_size, edges, weights, charges, node_ids, extras}`. Self-describing (undirected/unlabeled/metadata-free all round-trip). Class-K zig-zag sign (not the ALU magnitude-builtin).
