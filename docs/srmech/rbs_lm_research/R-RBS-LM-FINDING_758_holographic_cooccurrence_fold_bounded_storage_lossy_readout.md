# F758 — the co-occurrence store as a TRUE HDC object: fixed-width holographic fold (storage BOUNDED + LOSSLESS ✓, OVER-CAPACITY read-out crosstalks ✗, native op needed)

**Date:** 2026-06-15 · **srmech:** 0.7.5rc153 · **Composes:** F754/F757 (the EXPLICIT assoc/relations tiers — the `Counter()`-edge-dict the user caught growing to gigs), F584 (never flatten *everything* into one superposition; the over-capacity crosstalk tail), F119/F529 (two-tier: exact + holographic), F132 (Klein-4 HDC), the CLAUDE.md §2 STOP-list (`Counter()` for co-occurrence → use the HDC fold) · **User catch (2026-06-15):** "why on earth is an HDC object growing to gigs from the 1 MiB a tome starts with?" + "did we make bad requests to srmech?" · **Provenance:** `R-RBS-LM-HOLOFOLD_…py`; upstream ask UPSTREAM_NOTES §50/§50.1

> **Correction (2026-06-15, user direction "why is a chromosome lossy? that makes no sense"):** an earlier framing of this finding called the holographic store / tome "lossy by design." That was a mischaracterization. **A chromosome / genome / tome is LOSSLESS** — it stores exact leaves and exact payload text, byte-identical round-trip (UPSTREAM §49). **Loss is ONLY over-capacity superposition** — cramming MORE than a fixed-width HV's capacity of items into ONE bundle, so they crosstalk. That is a *sizing choice we size around* (more, smaller tomes each ≤ capacity; IDF so capacity isn't spent on stopwords), never an intrinsic property. The experiment below crosstalked precisely because it deliberately over-stuffed ONE bundle (every neighbour of a word, stopwords included). The text throughout now says **over-capacity crosstalk**, not "lossy."

## The catch, and why it was right
The F754/F757 co-occurrence tiers were built as an **explicit edge dictionary** (word → neighbour lists) — corpus-LINEAR, the exact `Counter()`-co-occurrence anti-pattern the framework's own STOP-list forbids. An HDC object should be **fixed-width**: N relationships SUPERPOSE into one bounded bundle; it must not grow with #edges. HOLOFOLD builds the store the framework actually promises: a streaming Klein-4 holographic fold (no edge list, no numpy, no Counter).

## Result 1 — STORAGE is bounded + fixed-width ✓ (the user's concern, answered)
2,000 simplewiki articles → **66,797 vocab**, store = **vocab × (D/4) = 4.3 MB** at D=256. **Per-word width = 64 bytes, CONSTANT** — independent of how many co-occurrences fold in. The store grows with **VOCAB (corpus-sublinear, Heaps)**, not EDGES (corpus-linear). So "the 1 MiB tome stays 1 MiB" holds: adding corpus *saturates the per-coordinate tallies*, it does not grow the object. **Big wiki is bounded by the same object that holds simple wiki.** The transient tally (vocab × D×4) was 274 MB and also corpus-INDEPENDENT in width (a native streaming op removes even that).

## Result 2 — the OVER-CAPACITY read-out crosstalks / is stopword-dominated ✗ (honest)
Holographic cleanup (top-6 by `klein4_similarity` over the top-3000 pool):
```
tea     : the(0.59) ceremony(0.39) and(0.39) black(0.38) green(0.36) drink(0.36)
dragon  : the(0.98) howard(0.35) eating(0.35) boat(0.35) destroyed(0.35)

computer: the(0.78) and(0.36) science(0.34) writers(0.33) voice(0.33)
```
Every bundle is **swamped by high-frequency stopwords** (`the`, `and`) — they co-occur with everything, so they dominate every superposition — plus superposition crosstalk (F584) supplies the rest of the noise. Contrast the EXPLICIT tier: `tea → ceremony, green, leaves, coffee`. The cause is **over-capacity**: this fold deliberately crammed *every* neighbour of a word (stopwords included) into ONE fixed-width bundle, past its capacity — so the bundle crosstalks. The **storage is lossless** (the leaves and the payload text are exact); only this over-stuffed read-out loses. Size around it and it is clean: (a) **IDF-weight the fold** (don't spend capacity on high-df words — what the explicit tier does via its stoplist; the dominant problem here, fully fixable), (b) **use more, smaller tomes each sized ≤ capacity** so no single bundle is over-stuffed; (c) the **residual crosstalk** (F584) is the small accepted cost of *deliberately* bounding the width for the long tail — why it's the *tail* tier, not the whole.

## Result 3 — it is too slow in pure Python (the §50 justification, live)
The fold ran **564 s for 2,000 articles** — O(D)-per-co-occurrence pure Python. At full corpus (240k articles) that is intractable. **This is the live proof of UPSTREAM §50:** the math is bounded + correct, but a holographic co-occurrence store needs a **native streaming `klein4_bundle_accumulate`** (standalone-C) to build at scale. srmech today has only BATCH `klein4_bundle` (needs all vectors resident).

## The architecture this settles (F119/F529 two-tier, now forced not optional)
- **EXACT tier** — small working set; explicit edges → eigen/Laplacian + O(1) clean neighbour lookup. (§17-U1 `cooccurrence_edges`.)
- **HOLOGRAPHIC tier** — bounded fixed-width fold for the long tail; **lossless when sized ≤ capacity**, and crosstalks *only* when deliberately over-stuffed past capacity (the accepted F584 tail tradeoff). (§50 `cooccurrence_fold` + `klein4_bundle_accumulate`.)
The over-capacity crosstalk here is not a bug to "fix away" — it is the cost you *choose* when you bound the width for the long tail, which is *why* the holographic store is paired with the exact tier (F584/F119/F529). **The chromosome / genome / tome itself never loses — only an over-stuffed bundle does**, and that is a sizing knob, not a property.

## Genome verdict (the deeper version of the question — UPSTREAM §50.1)
Audited whether §41–§46 delivered a non-holographic genome. The body IS linear (`turns.bin = 128 B × leaf_count`, measured). **But that is NOT a bad request** — a helix IS linear, and §41–§46 bought *addressability + editability* (cap-span excise) that a superposition cannot give. The non-holographic miss is in USAGE (one leaf per item), not the request; the fix is **tome-leaves** — one leaf = a §50-folded fixed-width bundle of many items — which the genome ALREADY accepts (a leaf is a Klein-4 vector). **No genome primitive to un-ask.** The shape that falls out: a linear addressable scaffold (the helix — keep) carrying holographic fixed-width units (tomes — the only missing op, = §50).
