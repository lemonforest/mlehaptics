## Verdict
**Largely yes — with one honest seam.** The **form layer collapses to a procedural procedure generator**: forms are not a list to collect — they are a small set of form-primitives (SEQ/NEST/REPEAT/CONTRAST/FRAME) *composed*. The form-space is **generated, combinatorial** (5 primitives → 63→213→353 by depth), not scraped. So *"more stories is just more data about stories"* and *"we can generate that anyhow"* — **yes**: we generate the form-space; we don't collect a story-corpus to learn forms. The "procedural procedure generator" you named **is** srmech's `cascade.compose` (atoms→composites), pointed at *form*-atoms — the framework's native move.

**So an encyclopedia reduces to:** `{ procedure-generator (forms) + attested content (facts) + the fixed seen engine + the Class-C intent chooser }`. The generator *replaces the story-corpus*; the content + intent are the non-generated parts.

**The honest seam (your "maybe", load-bearing):** the generator makes the **telling, not the truth.** Content stays **attested** (a generated "fact" is a hallucination — knowledge is referenced from the source of truth, never invented, F630/MPM); the **which-form choice** is Class C (the intent / which-way); and the irreducible residue (the specific meaning, the author's/expert's intent) is attested + chosen, never generated (F552/F282). So *"all we need is a procedure generator"* is **true for the form**, but content (attested) and intent (Class C) are the seams it does not cross — which is exactly right: **we generate how to tell, never what is true.** (And this is precisely why a data-center LLM can't factor it — all-flock, F636/F650, it can't separate generator/content/intent, so it re-learns the whole product and must bloat.)
