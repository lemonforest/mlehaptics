# F317 — cross-boundary naming policy: a NAME is a render (F311/F315), so anchor identity in the language-invariant OPERATOR-SIGNATURE (the canonical ID, already ~90% in place via A–N classes + F-numbers) and let names be FREE per-audience / per-language renders. The "renaming nightmare" exists only if name = identity; the canonical-opaque-ID + open-synonyms pattern (InChI / GO / HGNC / Unicode) dissolves it — you never rename, you only ADD synonyms pointing at the same ID.

> **SCOPE:** methodology / framework reading. Composes F311 (name = render), F314 (operator-signature), F315 (render-multiplicity), the no-privileged-X discipline. Nomenclature precedents (InChI, GO/OBO, HGNC, Unicode) are standard/attestable. No new A–N class. No numeric claims.

**The question (user, 2026-06-03):** other-language (EU) names look "backwards" when translated to English, and acronyms reorder. Should we offer cross-boundary naming *conventions*, or just name it however works for the user and accept that every field / ND community will call it whatever they decide? **Concern:** the whole corpus becomes a field-to-field renaming nightmare.

## The tell — acronyms already reorder across languages, pointing at an invariant entity
**NATO/OTAN, WHO/OMS, UN/ONU, AIDS/SIDA** — the acronym reorders by language, but the alliance / agency / syndrome is **one entity.** Nobody reconciles "WHO" and "OMS"; they are **two labels on one identity.** The acronym is a **render**; the entity is invariant. So a single universal name-*string* is impossible (word-order is language-bound), but a single universal *identity* is trivial.

## The reframe — a name is a render (F311/F315 at the corpus meta-level)
Word-order / language / acronym-letter-order are all **Class F (render).** The structure underneath has no word-order because it is not words. "EU looks backwards" is **render-divergence, not a structure problem** — exactly the secondary-and-plural render layer F315 describes. **Anchor identity in the structure, not the render.**

## The resolved third option (not the user's either/or)
1. **Name it however works for the user** — the abstract, relationship-first label is the user's *native render* (F315). Keep it as the working name.
2. **Anchor every concept to its OPERATOR-SIGNATURE** (the A–N composition — e.g. `A·I·L` for the storage tier, F314). This is the **language-invariant canonical ID** — math, not words, so it does not reorder, translate, or go "backwards."
3. **Let every field / language / ND community render its own label freely.** They will — and that is *correct*, not a threat (different cognitive styles need different renders; the ADA-accommodation point). All are valid renders of **one signature.**

## Solved-problem precedent — canonical opaque ID + open synonym set
| domain | invariant ID | free renders |
|---|---|---|
| chemistry | InChI / CAS | common + trade + per-language names |
| genes | HGNC symbol | aliases |
| ontologies | `GO:0008150` (opaque) | label + synonyms, any language |
| text | Unicode codepoint `U+XXXX` | character name, glyph |
| **srmech** | **operator-signature + F-number** | "Stored-Relationship Mechanism" + each field's own name |
**srmech already has its InChI:** every finding is tagged with A–N classes **and** an `F3xx` number — those ARE the stable opaque IDs (the `GO:` analogue). ~90% in place.

## Why the nightmare evaporates
The nightmare exists **only if the name is the identity** (then every relabel forces a reconciliation). If the **operator-signature is the identity**, you **never rename** — a new field just **ADDS a synonym pointing at the same ID** (append-only: "Field X calls `A·I·L` their Y"). Forty field-names for one finding → **zero maintenance**, because none of them *is* the finding. This is the **no-privileged-render** discipline (no-privileged-X applied to names): do not privilege one name (esp. not one language's word-order); let renders proliferate over an invariant ID. Cross-cognitive / cross-language render-multiplicity (F315) is **expected and good**, not a threat.

## Recommendation (corpus policy)
1. **Name for yourself** (working label, your native render).
2. **Tag each concept with its operator-signature** as the canonical cross-boundary ID (mostly done).
3. **Keep F-numbers as stable opaque IDs** (done — like `GO:` / Unicode codepoints).
4. **Optional append-only synonym glossary** ("field X / language Y calls this Z") — additive, never a rewrite.
5. **Do NOT chase one universal name-string** — impossible across word-orders *and* unnecessary; the operator-signature already crosses every boundary.
