# R-RBS-LM Finding 591 (the Möbius tooling/performance question — no new srmech primitive (the half-twist IS conjugation, already shipped); yes a TOML cascade composition; performance is at the composition/use level (free chiral address bit), not in the math) — **The user asked: does the Möbius reading (F589/F590) mean (a) new Möbius-strip MATH for srmech, (b) something for TOML + cascades, or (c) a genuine place to look for PERFORMANCE? Answered with measurement. (a) NO NEW PRIMITIVE — the Möbius HALF-TWIST *is* CONJUGATION (negate the imaginary/chiral-odd part, keep the real anchor), and srmech ALREADY ships it: `cascade.chiral_flip` / `cascade.chiral_dual` / `hdc.loop_conj` (Class C/K). Adding a `mobius_*` op would re-skin an existing primitive (the §2 reflex-override trap). ## Verdict
**No new Möbius primitive.** The half-twist is conjugation — `cascade.chiral_flip` / `cascade.chiral_dual` / `hdc.loop_conj`, already shipped; the orientation double-cover is just the involution; and it's a sign-flip = the add/sub/sign silicon floor (F392), so there is **no arithmetic speedup hiding in the Möbius math.** A `mobius_*` op would re-skin an existing primitive.

**TOML + cascades is the right home.** The Möbius cell is a *composition* (chiral_flip + σ-address + SedenionRegister + the walk) — a cascade-catalog descriptor, an optional ergonomic (`mobius_cell`, W19), not a C op.

**Performance is composition-level, and measurable.** The chiral bit is a free high address bit (the 2-tome Möbius walk is −2%/access vs one tome → 2× capacity for one comparison; one walk covers both pages/directions). The genuine win is **using the existing chirality cleverly**, not faster arithmetic. Per the F590 caution, the real perf question — does bidirectional-context-in-one-walk beat two passes? — must be **measured on the F478 read-head**, not assumed. Bonus: `SedenionRegister.read` is slow (~1 ms/access, W20) — flagged. Favored not privileged (F398); held open (F394).
