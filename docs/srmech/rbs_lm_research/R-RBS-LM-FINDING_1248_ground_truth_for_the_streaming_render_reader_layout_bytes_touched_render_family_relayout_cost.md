## A — Layout of the prepared directed Class-L genome
- **2 chromosomes** (from `manifest.json`, format_version **11**, leaf_dim **64**, n_turns **18,401,391**):
  | label | leaves | bytes | cap_sha256 |
  |---|---|---|---|
  | **graph** | 17,908,909 | 304,451,517 | c72cdf1c… |
  | **vocab** | 492,480 | 8,372,224 | 6af1787e… |
  So it is **ONE big `graph` chromosome** = a single `genome.graph_to_kernel(vocab_size, edges, metric, charge)` run over **all 39,048,148 directed edges** (metric + charge), **NOT per-token chromosomes**. The `vocab` 2nd chromosome is the `\n`-joined UTF-8 string table (each byte → 4 base-4 syms, `genome_append_kernel`).
- **Token addressing = a dense integer id = the token's position in the vocab table** (`vindex = {token: id}`). **NOT content-addressed** — there is no `sha256(token)`. The manifest offsets/caps are **chromosome-level (2 caps)**, not per-token; there is no per-node offset in the genome.
- **Sizes:** `turns.bin` 312,823,741 B (298 MB) · `manifest.json` 2,292 B · n_chromosomes **2** · n_edges **39,048,148** · vocab_size **831,139** · **~7.8 bytes/edge** on disk (src+dst+metric+charge via the 30-bit base-4 varint codec).
- **A2 — edge order: GLOBALLY SORTED BY SOURCE (CSR).** Empirically: head = `(0,·)×8, (1,·)×7, (2,·)…`; @25% src 143,761; @50% src 321,497; monotone throughout. `graph_to_kernel` **preserves input order byte-exact** (SIONA231 round-trip `graph["edges"] == input`), so **the coupled turns are per-source contiguous** — a node's OUT-edges are already a contiguous run in `turns.bin`. (IN-edges, "who-points-to-X", are scattered — that's why `build_reads` expands both directions into the cache.)

## B — Current read path + bytes-touched per mode (the load-bearing measurement)
The read path is `docs/srmech/siona/siona/corpus_store.py`. It has **three layers**: the genome (`turns.bin`+manifest, the store), the `reads/` cache (`adj.bin` **937 MB** + `adj.idx` 10 MB + `vocab.txt` 8 MB — the demand-load index), and the `tree/` cache (tomes/web/hubs/word_tome JSON, 3.6 MB — the Fiedler tome-tree). Measured live (rc269):

| read op | path | bytes-touched | time | source file |
|---|---|---|---|---|
| `prepare()` (demand) | mmap `adj.bin`, load `adj.idx`+`vocab.txt`+tree JSON | ~14 MB idx+tree (mmap ≈ 0 decode) | **1.0 s** | reads/ + tree/ |
| `read(tok, k=6)` | one idx rec + k neighbour recs from the mmap | **84 B** (12 + 6×12) | 5–9 ms | **adj.bin** |
| `etak_walk(6 steps)` | 6 hops × (idx + ≤48 recs) | **~3.5 KB** | 27 ms | **adj.bin** |
| `find` / `ride_tome` / `web_hop` | in-RAM tree JSON lookup | 0 store B | ~10 µs | tree/ (RAM) |
| `body_lead` | the SEPARATE `*fullbody_instrument.ndjson` (+index) via `bridge.recall` | — | — | **different store** |
| `load()`→`kernel_to_graph` (genome-native) | **decodes ALL of `turns.bin`** (39 M edges → RAM) | **313 MB** | **~21 min** | turns.bin |

- **B4/B5 — EVERY neighbour read goes through `reads/adj.bin` (937 MB = 3× the genome), NOT the coupled turns.** The ONLY genome-native neighbour path is `load()`→`kernel_to_graph`, which **whole-decodes** the 39 M-edge graph (~313 MB, ~21 min, multi-GB RAM). **There is NO way today to get one token's neighbours straight from the coupled turns** without either the `adj.bin` cache or the whole-graph decode — `kernel_to_graph(chroms, the_one, n_syms)` has no node-range / seek / partial-decode mode. Demand-read : whole-store = **84 B : 313 MB ≈ 1 : 3.7 million**.
- **B6 — coherency for an ordered read:** two natural orders exist. (1) **sorted-by-source** — ALREADY the on-disk order (CSR), so a node's forward-edge run is contiguous in `turns.bin`; only a per-node offset table is missing to seek it. (2) **the Fiedler/tome clustering** (`tree/`) = clumps-of-clumps — the coherency order that would let a cap-TOC descent (tome cap → node cap → edge-run) reach a token without a full body scan. (The de Bruijn **fiber** order, F806, is the *article*-fiber's order in the body instrument, not the co-occurrence graph's.) The `reads/` and `tree/` caches are today EXTERNAL to the coupled turns — the §876 target is to make them intrinsic.

## C — the EPH render family + the render findings
- **C7 the concrete walks:** **F806/F807/F808** — an article IS the **Eulerian-path fiber over its de Bruijn shape-graph**, and a **resonant fixed point (eigenstate)** of the RBS-HDC transition operator T: from a k-gram context retrieve the successor token (T), commit the unambiguous one, repeat → **T(article)=article**, reproducing it exactly at k≥k* (the context key must be a **bundle record**, not an XOR-fold, for monotone 100%). **F1080/F1213** — the **unicursal / Eulerian CIRCUIT** render (sandroing, UNESCO 00073): one continuous line, every edge once; drawable as ONE stroke IFF the graph is connected + all-even-degree, else `odd_degree//2` strokes; F1213 = the directed glyph-graph encoder, genome-native. **F1061 (EPH)** — `harvest = Propagate · excite = P(E)`, the op⊗operand cascade; the neuron is just one choice of P; **THERMAL** `P=e^{−tL}` (the etak/classical/observer regime) vs **COHERENT** `P=e^{−itL}` (the unitary quantum walk). **F1096 (dark sector)** — genome = total content; the **expressed** subset (`gene_express` under a `cell_state`) = the active excitation (read/luminous); the **un-expressed** genes = the dark sector (exists, unread); `cell_state` = cellular coherence navigating from the seeded excitations — so **gene_express/chromatin IS the demand-load: express only the active subset**. **F742** — inference = an **etak-walk over the co-occurrence surface**.
- **C8 — corpus_store ops ↔ find / ride / enter-ride-exit (ephemerides ITN):**
  - **FIND all corridors in a band** = `find()` (descend the tome-tree to the token's tome/band) + `read()` (all 1-hop corridors touching X).
  - **RIDE one** = `etak_walk()` (ride ONE directed corridor by moving the reference frame — chirality-consistent strongest-coupling hops, the fwd/bwd chiral fronts) / `ride_tome()` (the tome's coherent ridge).
  - **ENTER-RIDE-EXIT X→X′** = `web_hop()` (cross the strongest bridge from tome A to adjacent tome B — the cut-edge web, the cross-tome relationship one tome can't see). **One question ≠ one answer**: find(band) → ride(corridor) → web_hop(transfer) is a multi-corridor traversal — exactly the ITN pattern.
- **C9 — distributed-index / coherency-ordered read:** **no existing finding specifies a distributed cap-TOC, no-`.idx` read** — that principle is NEW here (§876). The current design has a SEPARATE `adj.idx` + `adj.bin` cache, which is precisely the **F1247 anti-pattern** (a re-encoded, decode-me-later side store). The manifest cap-TOC is chromosome-level (2 caps), not per-node. This is the gap the streaming reader closes.

## D — re-layout cost
- **The good news: edges are ALREADY globally sorted-by-source, so per-node forward-edge contiguity EXISTS in the coupled turns.** A genome-native per-node read needs only two ADDITIVE things, not a re-encode: **(1) a per-node distributed cap-TOC** — `node_id → (turn_offset, out_edge_count)` carried IN the genome (a caps table / a 3rd chromosome), and **(2) a seek/partial decode** — a `kernel_to_graph` variant that decodes a single node's edge-run from `(turn_offset, count)` rather than the whole chromosome. Those two turn the 84-byte demand read into a **coupled-turns** read and **eliminate the 937 MB `adj.bin`**. (Backward-neighbours need either a 2nd sorted-by-target copy or accepting the forward `etak` sense only.)
- **If a re-sort IS wanted** (order the node layout by **tome**/Fiedler clump so the cap-TOC descent = clumps-of-clumps and `tree/` becomes intrinsic): sort 39 M edges = O(E log E) ≈ seconds; the genome build was ~1516 s (~25 min) last time → **~25 min one-time, encode-once**. Not required for the additive per-node index; only for clump-locality.
- **`write_packed_graph` is NOT the store encoder** and is **not load-bearing for the render reader.** It writes a Fiedler scratch adjacency (16-byte `uint32 u | uint32 v | double w`, undirected) that `fiedler_sparse_file` / the out-of-core `recursive_cut` reads (§52/F793) — i.e., **input to the TREE clustering**, orthogonal to the coupled-turns store (which is `graph_to_kernel`). It is removable-in-favour-of-coupled-turns only if the Fiedler clustering is refactored to read the graph chromosome directly; it does not stand between us and genome-native reads.

## The srmech asks (design requirements for the streaming render reader)
1. **Per-node distributed cap-TOC** — carry a `node_id → (turn_offset, out_edge_count)` index IN the genome (additive over the existing CSR/sorted-by-source layout; a caps table or a 3rd chromosome), so a query seeks node X's edge-run with no prefix decode. This IS the "distributed index, no separate `.idx`".
2. **Seek / partial `kernel_to_graph`** — decode a NODE RANGE (or a single node's edge-run) from `(turn_offset, count)`, not the whole chromosome. This is the one missing primitive that makes the coupled turns per-node readable and retires `adj.bin`.
3. **Chromatin-gated expression over the seekable store** — wire rc269's `gene_express` / `chromatin_of` / `cell_state` so a query EXPRESSES only the walked subset (the active excitation, F1096), reading from the seekable turns rather than a cache. rc269 ships the markers; the missing bridge is (2).
4. (optional) **coherency-order the node layout by tome** (Fiedler clumps) so the cap-TOC descent is clumps-of-clumps and `tree/` becomes intrinsic instead of an external cache.
