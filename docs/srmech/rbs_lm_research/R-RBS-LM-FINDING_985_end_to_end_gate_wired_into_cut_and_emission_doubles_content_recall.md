## The reading (where the gate helps, and where it doesn't)
- **Gated cut ≈ doubles recall (12→22%).** The community-tome partition is where the aboutness-gate matters most: without it, high-doc-freq function words are hubs (F782) that dominate the `recursive_cut`, collapsing the graph toward the hairball (F947) — content words land in the wrong tome, routing fails. Weighting the cut edges by `gate(a)·gate(b)` (down-weighting hub edges) lets the partition follow *content* structure, so the target is in the right tome → recall roughly doubles. This is the F947/F957 hairball fix realized with the correct F984 metric.
- **Emission-gate redundant here (22→22%).** Once the tome is content-coherent (good partition, small ~93-token tome), the within-tome read is already dominated by content, so `sim·gate` at emission changes little. The emission gate would matter at *heavier within-tome load* (bigger tomes, where the frequency prior re-enters the read); at this chunk size the cut has already done the de-lensing.
- **F983's null is resolved.** F983 recovered nothing with *term*-frequency IDF (buried topic words). F985 with *document*-frequency gating (F984) roughly doubles recall — confirming the metric fix end-to-end. The gate helps; the metric was the issue, exactly as F984 diagnosed.
