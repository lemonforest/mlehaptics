## §3 The two-substrate framework reading

### §3.1 Mechanism 1 + Mechanism 2 are parallel substrates, not alternatives

R-RBS-LM-37 framed M1 and M2 as substrates that the cascade chose between (it landed in M1; M2 was the source). That framing was incomplete. **In actual operating systems both substrates run, with translation operators between them.**

Where each lives:

| Substrate | Hypervector type | Operations | Role |
|---|---|---|---|
| **M1** (discrete-cyclic-algebra) | Bit-exact bipolar (corners of hypercube `{−1, +1}^D`) | Bind (XOR / permutation); bundle (majority); popcount similarity | Compositional storage; relationship-of-relationships; exact content addressing |
| **M2** (continuous-Hopf-quantum) | Continuous stochastic (real-valued `R^D`) | Soft-mix; weighted sum; attention; rotation | Continuous interpolation; smooth transitions between related concepts; rotation-bearing |

LOGO already operationalizes this coexistence: **`bundle_sum` is the M2-like phase (unbinarized real-valued accumulation preserving linearity)**; **the final cleanup-to-codebook is the M1-like phase (snap to nearest corner)**. The pattern works only when both phases are present in the right order.

R-RBS-LM-37's "rotation is substrate-property of continuous representations" remains valid — but specifically, rotation is **M2-native**. M1 has its own substrate-physics (permutation-rotation via bind; algebraic role-swaps via unbind+subtract+add per LOGO L1 corrected primitive). **Neither substrate is "the substrate"; both are required.**

### §3.2 Projection operators (B/H/N) mediate between substrates

The 14-class vocabulary's meta-cascade triad maps cleanly:

| Class | Operation | Cross-substrate role |
|---|---|---|
| **B** (TLV-framing) | Type-length-value framing | Wraps M1 content with metadata for M2-consumer rendering; or wraps M2 query for M1-substrate evaluation |
| **H** (Self-introspection) | Reads internal state for external rendering | Surfaces M1 substrate state to M2 observer/projector |
| **N** (Rational-approximation) | `best_rational(num, denom, max_d)` — maps continuous values to nearest rational | **Direct M2 → M1 projection** — continuous real to discrete rational; the substrate-translation primitive |

LOGO's fiber matrices ARE B/H/N composition in operational form. F₁'s `M₁ᵀ · Δa` projects atom-deltas to syntax space (an N-like quantization operation); F₂'s `M₂ᵀ · Δs` projects syntax-deltas to geometry; chained `M₁ᵀ → M₂ᵀ` IS the multi-stage translation between M1 substrate and M2 surface. R-RBS-LM-40 design space inherits this: **the projection layer doesn't have to be invented; B/H/N composition is the existing template.**

### §3.3 External projection is an architectural requirement, not a workaround

R-RBS-LM-37 treated language projection as an OPTIONAL surface layer. Under the two-substrate framing it's **architecturally required**: the M1 substrate stores byte-relationships; the consumer (English reader, ASL signer, ITN-routing dispatcher, astronomer reading orbital reports) operates in M2 conventional-language; **B/H/N translation between them is part of the architecture, not an afterthought.**

Worked examples across subtrees:

| Subtree | M1 substrate output | M2 conventional surface | Translation layer |
|---|---|---|---|
| Ephemerides-spectral | Orbital cycle ratios; geodetic catalogs | "Mars is in retrograde"; "Saros cycle predicts eclipse 2024-04-08" | Astronomer applying conventional astronomical vocabulary (external visual inference) |

**Same architecture; different consumer; different projection.** The cascade doesn't need different substrates for each — it needs the same M1 substrate WITH the appropriate B/H/N projection layer at the output.

### §3.4 Proper nouns and naming layer are heavy lifting

User-direction 2026-05-26: *"people words are not natural and must have some heavy lifting work."*

Three categories distinguished:

| Layer | Examples | Cost shape |
|---|---|---|
| **Substrate-emergent vocabulary** | "tree", "running", "blue", "two" — concepts that emerge from frequency patterns in the substrate | Cheap; substrate stores these naturally as byte-relationship attractors |
| **Class-noun vocabulary** | "star system", "chess opening", "polygon", "person" — categorical labels for substrate-recognizable classes | Moderate; requires anchor to a class definition but the class itself may be substrate-emergent |
| **Proper-noun instance vocabulary** | "Sol", "Sicilian Defense", "hexagon", "Steven Kirkland", "ITN highway A-to-B at 14:30 for holding-pattern Charlie" | **Heavy lifting**; conventional anchoring; not derivable from substrate frequency; requires explicit lookup or external naming layer |

LOGO's quantum-numbered atom requirement is the worked example: random atoms fail; quantum-numbered atoms (5 roles: category/arity/argtype/reverse_axis/block_opener) succeed. **The conventional vocabulary (FORWARD/BACK/LEFT/RIGHT/REPEAT/etc.) is heavy lifting in LOGO too** — it requires structured anchoring via quantum-number bindings to be substrate-friendly. Random word-mints don't work.

## §5 Findings

**Finding 1 — Two-substrate coexistence is the corrected framework reading.** Per §3.1. M1 (discrete-cyclic-algebra) and M2 (continuous-Hopf-quantum) both run in operating systems; not alternatives. LOGO's `bundle_sum` vs `bundle` IS this pattern in operational form.

**Finding 2 — B/H/N projection-enablers are the architectural translation operators between M1 and M2.** Per §3.2 + CLAUDE.md §1 + PR #680 R30. The 14-class vocabulary's meta-cascade triad already names this slot; LOGO's fiber matrices implement it in operational form.

**Finding 3 — External projection is architecturally required.** Per §3.3. Ephemerides / chess / LOGO / RBS-LM all need an external translation layer between substrate output and consumer-language surface. **Not a workaround; part of the architecture.**

**Finding 4 — Proper nouns / naming vocabulary is heavy lifting.** Per §3.4 + user direction 2026-05-26. Conventional anchoring requires structured encoding (LOGO quantum-numbered atoms); random encoding fails. Names don't emerge from substrate frequency — they're external naming-layer work.

**Finding 5 — Naming-layer cost asymmetry is cross-substrate, with crossover with substrate-scaling cost.** Per §3.5. Pattern visible across 8+ subtrees (chess / antikythera / ephemerides / doom / chess-4D / othello / LOGO / RBS-LM). Refined claim: **fixed naming cost + scaling substrate cost; crossover point depends on problem scale.** At all serious-problem scales, substrate operations dominate; naming-layer is the heavy engineering.

**Finding 6 — Substrate-foreign operations fail consistently; substrate-native operations succeed consistently.** Per §3.6 + R-RBS-LM-19 + LOGO L1 retraction. **Two independent partitions in different subtrees converged on this finding.** Substrate self-defends against operations that don't match its physics.

**Finding 7 — Substrate can self-bootstrap projection structure from coincidences given quantum-numbered atoms.** Per LOGO L6d. The F₂ fiber inferred the D₄ character table without being told. **This is the substrate doing its own projection inference**, which suggests R-RBS-LM-40 projection layer may not need to be hand-engineered — it may be substrate-learnable given structured-atom encoding.

**Finding 8 — R-RBS-LM-37's "rotation is M2-only" was too tight.** Per §3.6 falsifier table. M1 HAS rotation (permutation via bind; algebraic role-swaps per LOGO L1 corrected primitive). Just not CONTINUOUS rotation. **Refined**: M1 rotation is discrete + role-level; M2 rotation is continuous + token-level mixing.

**Finding 9 — R-RBS-LM-40 candidate space expands to 5.** Per §3.3 + §3.4 + LOGO L0-L7 pattern. Adding candidate **E: projection to constrained structured action vocabulary** (LOGO-style with quantum-numbered atoms) which is substrate-honest in a way the original A-D weren't, AND **R-RBS-LM-44 turtle-walk is the first test of candidate E.**

**Finding 10 — The LOGO arc was already validating this framework reading.** Per §2 + §3.1 + §3.4 + Findings 6+7. The user's 1980s-era childhood LOGO experience grounded a structural-language reading that this 2026 research is independently rediscovering. Per `[[user_stance_cross_substrate_cascade_matching_as_research_method]]` + user-authorized self-arc lineage: not coincidence; the methodology working as designed.
