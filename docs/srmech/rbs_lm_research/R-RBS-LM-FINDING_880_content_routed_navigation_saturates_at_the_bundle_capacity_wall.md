# F880 — Content-routed navigation BUILT + scaled off the toy; it works but SATURATES at ~0.70 @ 2000 pages — the F871 capacity wall is the addressing limit ONE LEVEL UP. "Resonate to find the page the query wants" (F879's next step) is built: each article = a page with a sparse routing **signature** (a Klein-4 bundle of its phase-keyed context-keys — the order/phase-aware contexts it knows, **NOT a bag of content words**); a stored query-context resonates against the signatures (the resonator one level up), `navigate`s to the winner, then phase-keyed within-page streams (F879). Measured on 2000 real simplewiki articles (6.7× off the 300 toy): **flat routing = 0.70** (a stored context → its home article), end-to-end **route→navigate→reproduce = 4/5** (the routed page always reproduces *itself* exactly — F879 holds; the one miss routed to a wrong article that still streamed cleanly). Two honest negatives: (1) **chunking the signature did NOT help** (0.71) — falsifies "within-signature crowding is the bottleneck"; the bottleneck is the query key competing against 2000 distractor bundles. (2) The **naive hierarchical index FAILED** — flat √N groups 0.28, base-16 small-fanout 0.16 — greedy descent through summarized node-signatures commits to the wrong branch early. **The limit is bundle-based (HDC/VSA) addressing itself: a superposed signature saturates as the corpus grows** — exactly the storage-density question now queued (the overstuff/Bekenstein/dark-ratio items).

## Measured (sparse, srmech-native; 2000 articles)
| router | accuracy (stored context → home article) | cost / query |
|---|---|---|
| flat resonance (flat bundle sig) | **56/80 = 0.70** | 2000 sims |
| flat resonance (chunked sig, SC=4) | 57/80 = **0.71** | 2000 sims |
| hierarchical √N round-robin groups | 22/80 = 0.28 | ~89 sims |
| hierarchical base-16 small-fanout, depth 3 | 13/80 = 0.16 | ~39 sims |
- **End-to-end** (route → `navigate` → phase-keyed stream): **4/5** exact. The routed page *always* reproduces itself (F879 = solid); the miss (art 100 → routed 1708) still streamed art 1708 exactly — the failure is in the **router's discrimination**, never the recall layer.
- vs chance (1/2000 = 0.0005), 0.70 is a strong routing signal — but it **degrades** from the toy's ~1.0, and that degradation is the finding.

## What the two negatives mean (diagnostic, not just failure)
- **Chunking the signature didn't lift it** → the bottleneck is NOT crowding *within* a page's signature (a page only holds ~12 keys, under the ~24 wall). It is the **query key competing against 2000 distractor bundles**: with N distractors each carrying chance-resonance, ~30% of the time a distractor beats the true member. This is the F871 wall acting on the *router*, scaling with **corpus size N**, not with per-page length.
- **The hierarchy made it worse** → a node-signature that summarizes ≤16 children (even chunked) cannot discriminate faithfully enough for a *greedy* descent; one wrong turn high in the tree is unrecoverable. Bundle-of-bundles loses the very membership signal the leaf needed. So the O(log) addressing (F873) is **not** free — a faithful hierarchical index needs more than superposed summaries.

## Honest scope
- **Reproduction-routing** (F841): the query is a *stored* context; routing it to its home page is recall-addressing, not novel-query semantic search (that's the generalization axis, F867, untouched). 0.70 is the stored-context routing rate at 2000 pages.
- **Scale:** 2000 articles (6.7× off the 300 toy), tractable in a REPL. **Full simplewiki (271,174 articles, the v082 instrument — already encoded) is an offline batch**: 271k signatures × 8KB (1-byte/slot Klein-4) ≈ 2.2 GB, which is exactly where the F871 **2-bit packing** pays (4 slots/byte → ~540 MB). The encoding exists; materializing all page-signatures is a streaming pass, not a single run — and the router would saturate *further* at 271k, which is the open problem, not a missing build step.
- Sparse held: Klein-4 signatures + resonance routing + sedenion-grid `navigate` + phase-keyed stream; exact-`Q` ranking; **no dense, no numpy, no bag, no gen-1 pattern**.

## Verdict / next
Content-routed navigation is **built and honest**: resonance over per-page signatures routes a stored context to its home article at **0.70 @ 2000**, end-to-end the pipeline reproduces exactly whenever it routes right, and the recall layer (F879) is untouched-solid. But routing **saturates** — superposed (HDC/VSA) addressing has a corpus-size capacity wall, and naive hierarchy can't dodge it. This is the **storage-density limit** of bundle-based addressing, and it motivates the queued research items (2026-06-20): **inference-as-overstuff** (does biology's story-generation = the single-M overpack past capacity? — with the false-memory caveat), a **maximum knowledge-saturation magic number** (Bekenstein / holographic bound), **universe-scale resonant encoding beyond HDC/VSA**, and **dark-to-baryon ratio as an information storage-density clue**. The router, not the recall, is now the frontier — and it may need a non-superposed address.
